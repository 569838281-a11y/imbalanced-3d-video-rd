一、背景与动机
--------------------------------------------------------------------------------
  用户反馈：优化后的 decoupled 训练每 epoch 约 2 小时，15 轮合计 ~30 小时，不可接受。

  实测慢路径瓶颈（experiment=non_rd_vs_rd/resnet3d_decoupled + erdes_gpu）：
    • 每 step 在线 PyAV 解码 mp4（~7 s/step）
    • Windows 上 num_workers=0（避免 error 1455 共享内存死锁）
    • batch_size=4 → 969 steps/epoch
    • GPU 侧 defer_resize 预处理

  969 × ~7 s ≈ ~2 h/epoch，与日志一致。

  第二次更改（second_summary）已设计 D 盘 tensor 缓存 + resnet3d_decoupled_fast，
  但缓存从未构建。本次第六次更改：落地并行建缓存、完善 fast 配置、一键启动脚本，
  并停掉仍在跑的慢路径训练，改走 fast 路径。

    • batch_size 4→8、num_workers 0→2、prefetch_factor=2
    • persistent_workers=true（缓存读取轻量，Windows 上可安全使用少量 worker）

四、慢路径 vs 快速路径对比
--------------------------------------------------------------------------------

  项目                    慢路径 (decoupled)          快速路径 (decoupled_fast)
  --------------------------------------------------------------------------
  数据配置                erdes_gpu                   erdes_cached

    powershell -File scripts/start_decoupled_train_fast.ps1
    # 或
    python -u erdes/train.py experiment=non_rd_vs_rd/resnet3d_decoupled_fast model.gpu_preprocess=false

七、注意事项
--------------------------------------------------------------------------------
  • 勿与 Grad-CAM / 其他 train.py 同时占 GPU（fifth_summary 可视化会严重拖慢训练）。
  • 8GB 显存若 OOM：data.batch_size=6 或 4。
  • Windows 在线解码必须用 num_workers=0；读 .pt 缓存可用 num_workers=2。
  • test  split 缓存可选（训练/验证不强制）；推理或 test 阶段再 build 即可：
      python scripts/build_video_cache.py --split test --workers 2
  • 快速路径日志：D:\ERDES\logs\decoupled_fast_train.log
  • Hydra 输出：logs/train/runs/rd/resnet3d_decoupled_fast/<timestamp>/
