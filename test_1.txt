一、总目标（一句话）
--------------------------------------------------------------------------------
在 Kaggle 上训练更强的 RD 判别模型（UM 锐化 + 二阶段解耦，约 50 epoch），
并为「先判视网膜脱离、再判黄斑完整性」的二级分类做好准备；
同时用现有最佳 Decoupled 模型做病灶定位初尝试（融合 CAM + ONSD 文
选帧/ROI 思路），效果好再移植到新模型，并为平台「依据区」供料。


二、三条工作流与优先级
--------------------------------------------------------------------------------

  A. Kaggle 强化训练（UM + Decoupled，50 epoch）     ← 中期主模型
  B. 二级任务准备（RD → 黄斑是否脱离）               ← 与 A 并行做标签/协议
  C. 定位初尝试（Decoupled + 机器预标流水线）         ← 本地可立刻开

  依赖关系：
    C 不阻塞 A；
    C 验证通过后再把定位方案迁到 A 的新权重；
    B 的训练可等 A 骨干稳定后进行，但标签与级联协议应尽早定。
    ONSD 论文方法主要进入线 C 与平台解释层，不替代线 A 训练。

四、线 A — Kaggle：UM + 二阶段解耦，50 epoch
--------------------------------------------------------------------------------
目标：
  • 数据侧：Unsharp Masking（UM）离线缓存或等价预处理
  • 训练侧：Decoupled（Stage1 Mixup 全网 → Stage2 冻骨干 + Logit Adjustment）
  • max_epochs ≈ 50；checkpoint 监控 val/f1（或 PR-AUC），不要只盯 Acc
  • 保留 PR 阈值搜索；注意修复 fp16/fp32 与回调冲突问题

策略提示：
  • Stage1 = epoch 1–38，Stage2 = 39–50（已写入配置）
  • 早停看 val/f1，防止 Stage2 震荡覆盖最佳权重
  • 对比表：Baseline / 旧 Decoupled(15) / 旧 UM / 新 UM+Decoupled(50)

交付：
  • Kaggle 最佳 ckpt + 指标表（含详细 Recall）+ 可复现配置/Notebook
  • 入口：docs/KAGGLE_UM_DECOUPLED_50EP.txt
           scripts/kaggle_train_um_decoupled_50ep.py


五、线 B — 二级分类准备（黄斑是否脱离）
--------------------------------------------------------------------------------
临床 / 产品逻辑（级联）：
  1) 是否视网膜脱离（RD）—— 一级，当前主任务
  2) 仅当倾向 RD 时 → 黄斑是否受累 / 完整性 —— 二级

当前可做的准备（未必要马上训满）：
  • 从路径或临床表整理标签（现有数据中可见 Macula_Detached 等线索）
  • 协议选型：级联（先 RD 门控）更贴 AI 医生问诊顺序，便于解释
  • 划分防泄漏：同一患者 ID 不要跨 train/val
  • 二级指标单独统计（在真 RD 或高置信 RD 子集上）

交付：
  • 带黄斑标签的划分表（或 CSV 增列）+ 任务说明一页
  • 后续在稳定 RD 骨干上加二级头或级联第二模型

  • 不学其临床目标：ONSD/颅压测径 ≠ RD 分类；解剖先验不可原样照搬

6.1 线 C 机器预标流水线（落地顺序）
--------------------------------------------------------------------------------

  步骤 C0  输入对齐（sampled_96，与训练一致）
      │
      ▼
  步骤 C1  【模型关注】Decoupled Grad-CAM / Top-K 帧能量
            → 候选关键帧 + 高亮外接粗框
            （现有 GradCAM3D；预标字段 prelabel=cam）
      │
      ▼
  步骤 C2  【帧质量分｜借鉴 ONSD 选帧思想】
            对每帧打 quality_score（回声/对比/边缘清晰度，或
            超像素与「RD 膜样高回声条带」粗先验的重叠分）
            → 选出 Top 质量帧，与 C1 取交或并集扩召回
            （对应论文：SLIC + 模板匹配选最优帧；此处换 RD 先验）
      │
      ▼
  步骤 C3  【ROI 时序平滑｜可选，借鉴 KCF 跟踪】
            对 C1/C2 粗框做帧间跟踪/粘连，得到稳定病灶带
            → 减少单帧闪烁假阳性
      │
      ▼
  步骤 C4  【规则过滤】
            过小框、贴边伪影、单帧闪现、与 PVD 易混模式降权或丢弃
      │
      ▼
  步骤 C5  【一致性可选】再跑 UM-CAM，保留两路都同意的框
      │
      ▼
  步骤 C6  【人工改框】按 docs/RD_WEAK_ANNOTATION_SPEC.md
            初级标注员改；难例/锁定测试集医学复核
      │
      ▼
  步骤 C7  【验收】Video-Recall / Normal FP / vs 纯 CAM 基线 / 盲评
            达标 → 移植到线 A 新 ckpt；写入平台「依据区」JSON

6.2 输出约定（进入平台依据区）
--------------------------------------------------------------------------------
  findings[]:
    frame_idx, box_norm, score, source∈{cam, quality, track, human}
  evidence_text:
    「模型关注区 + 成像较清晰帧」类表述；禁止写成病因/已确诊解剖结论

交付：
  • 预标 JSON 样例 + 与纯 CAM 基线对比 +「是否值得移植」结论
  • （计划）scripts/prelabel_* ：CAM → 质量分 → 过滤 → JSON

说明：
  • 定位产出是「影像可疑区域」，不是病因
  • 不必全部由主任医师标注；规范与验收集需医学把关

八、平台愿景（与总流程对齐）
--------------------------------------------------------------------------------
  • 上传眼部超声 → AI 辅助结论 → 依据（线 C findings）→ 医嘱模板
  • 后续对话补病史，辅助判断（非替代执业医生）
  • 判别 / 定位 / 病因叙述 必须拆开，禁止用 CAM 直接当病因
  • ONSD 文贡献的是「视频自动化中间层」产品形态，不是第二套病种模型

--------------------------------------------------------------------------------
